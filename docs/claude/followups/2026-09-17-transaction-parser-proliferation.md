# Follow-up: six parsers of MFL's `transaction` field, and one of them is inverted

## Why this exists

#1156 fixed one ad-hoc parse of MFL's roster-move `transaction` string. #1159
(F2 of that brief) found a second and a third, held all three to one recorded
corpus, and made the parity test able to fail. The cross-cutting pass on #1159
then swept the repo for `.split('|')` and found **three more**, one of which is
a live correctness bug of the same class as the original incident.

#1159 deliberately did not grow into them: they sit in different features with
their own guard suites, and widening a parser PR into the offseason-hero path
is the same wrong trade the original brief refused for the contracts path.

## The census

Six places read the same MFL field. Three are now held to the shared corpus by
`tests/contract-eligibility.test.ts`; three are not.

## F1 — `getRecentPickups` reports the players a team CUT as its recent pickups

`src/utils/offseason-hero-data.ts:999`, in the FREE_AGENT branch:

```ts
// FREE_AGENT format: "|addedId1,addedId2,|droppedId1,droppedId2,"
const parts = txnStr.split('|');
const added = (parts[1] || '').split(',').filter(Boolean);
```

**The comment is wrong, so the code is wrong.** There is no leading pipe before
the add side. The real format is `"added,|dropped,"` — `parts[0]` is the add
side and `parts[1]` is the DROP side. Verified against the real shapes:

| string | what really happened | what this reports |
|---|---|---|
| `"12464,\|9122,"` | added 12464, cut 9122 | **pickup: 9122** (the cut player) |
| `"\|11957,"` | pure drop of 11957 | **pickup: 11957** (nothing was added) |
| `"11957,\|"` | added 11957 | **no pickup** (misses the real one) |
| `"\|12169,12857,"` | bulk drop of two | **pickups: both cut players** |

The pure-drop row is the #1156 phantom-pickup bug verbatim: the empty add
segment is read as if it held the added player.

Dormant in-season — `offseason-hero-data.ts` feeds the offseason hero and cut
watch — which is why it is a follow-up and not a hotfix. It fires in the
offseason.

Consumer: `getRecentPickups` is called once, at `offseason-hero-data.ts:1042`.
Establish what that surface shows before changing the shape of the return.

## F2 — the two unpinned-but-not-wrong parsers

- **`src/utils/mfl-transactions.ts:306` is the best implementation in the
  repo** and worth reading before writing any of this: it is type-aware,
  indexes segments rather than counting them, and its own comments name the
  three traps. It reached the same design #1159 converged on independently. It
  is simply not in the corpus test, so nothing stops it drifting. Add it.
  (Minor, same class as #1159: its BBID drop side does not filter the `0000`
  nothing-cut sentinel.)
- **`src/utils/schefter-transaction-parser.ts:84`** still carries the
  `.replace(/^\|/, '').filter(Boolean)` pattern — the one that erases the empty
  add segment — plus a `num > 100_000` heuristic to tell a salary from a player
  id, and it returns a flat list with no add/drop side at all. Its only
  importer is its own test (`SchefterPostCard.astro` merely names it in a
  comment; `transactions-live-merge.test.ts` imports `parseDraftPickId` and
  `parseTradeAssets` from it, not this function). **Decide whether it is dead
  and delete it** rather than leaving a known-bad parser where the next person
  can find and reuse it.

## The real fix, if it is worth it

Six implementations is the actual finding. The corpus parity test is a good
holding pattern but it is a ratchet against drift, not a cure — every new
parser has to be remembered into it. One parser in `src/utils/`, imported by
both the app and `scripts/`, would end the class. That is a real refactor with
its own blast radius (the scan guard in
`tests/article-transaction-parse-guard.test.ts` names the current path, and
`schefter-scan.mjs` and `waiver-pickups.mjs` both import it), so it wants
`/feature` and a design gate, not a free hand.

## Context to start cold

- The corpus is `tests/fixtures/mfl-transaction-strings.json`, regenerated by
  `node scripts/record-transaction-shapes.mjs` — offline, reads the committed
  feeds for every league and season, no API key. 37 distinct (type, shape)
  pairs over 36,471 rows.
- The grammar, settled in #1159: three segments is `add | price | drops` (the
  comma after the add id is optional, the price may be decimal); two segments
  is `add | drops`, except on `AUCTION_WON` where it is `add | price` — and
  only the row's `type` can tell those apart. `0000` in a pre-2017 drop segment
  is a nothing-cut sentinel, not a player.
- `docs/claude/rules/schefter.md` § "A parity test is only as strong as its
  corpus" carries the rules; the path-guard note on the `contracts-eligibility`
  domain carries them mechanically.
